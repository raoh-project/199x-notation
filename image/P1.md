# P1

P1 is the first format a machine is written in as an image, so that a machine one implementation
built runs on another. This file is its definition: what text is an image of P1, and what an image
that is one accepts. It is not taken from any implementation's code, and every implementation that
reads or writes P1 is held to it. How a pattern becomes a machine, which machine an implementation
writes, and how many characters it writes at most are not part of the format; the
[README](../README.md) says what a writer promises.

## What an image is written in

An image is text in ASCII. It begins with the marker `P1`, and after the marker comes a sequence of
numbers, each one after a comma:

```
image  = "P1" 1*( "," number )
number = "0" / ( %x31-39 *%x30-39 )
```

So a number is 0 or decimal digits that do not begin with 0. Nothing else is written: no sign, no
space, no line break before, inside or after the image, no empty number between two commas, and no
comma at the end.

Every number is an integer from 0 to 2,147,483,647, and a text with a larger one is not an image of
P1, wherever the number stands and however many digits it has. A place may allow less, as the
sections below say. A later format that needs larger numbers is another format.

## The numbers in order

The numbers are, in this order:

1. The kind: 1 for a deterministic machine and 0 for one that is not.
2. The number of sets, and then each set: the number of runs it holds, and then each run as its
   first and last scalar value.
3. The number of states, and then each state: 1 where a walk that ends there accepts and 0 where it
   does not; the number of its steps, and then each step as the set it is over and the state it
   leads to; and the number of its free steps, and then each as the state it leads to.

Sets and states are numbered from 0 in the order they are written, and a step names them by those
numbers. The image ends with the last number of the last state.

`a+`, for example, is one set, of the one run `a`, and two states, of which only the second
accepts:

```
P1,0,1,1,97,97,2,0,1,0,1,0,1,1,0,1,0
```

State 0 steps over set 0 to state 1, and state 1 steps over set 0 to itself. Neither has a free
step. The same machine is deterministic, and written as one it begins `P1,1,`.

## What makes an image one

An image is one where all of these hold:

- The kind is 0 or 1, and so is whether each state accepts.
- A count, of sets, runs, states, steps or free steps, is at most 2,147,483,647, as every number
  is, and the image holds as many of what it counts as the count says.
- Each run is of scalar values: its first is no greater than its last, its last is at most 1114111
  (U+10FFFF), and it holds no surrogate, 55296 to 57343 (U+D800 to U+DFFF). The runs of a set are
  in order and do not overlap: each begins after the one before it ends. Two runs may be next to
  each other, as 97 to 97 and 98 to 98 are. A set may hold no runs.
- There is at least one state.
- A step names a set the image has, and a step or a free step names a state the image has.
- A deterministic machine has no free steps, and no two steps out of one state are over sets that
  have a scalar value in common. Two steps over a set that holds none have none in common.
- Nothing follows the last state.

Nothing else is asked. Two sets may hold the same runs, a set no step is over and a state no walk
reaches may be written, and the steps of a state may be in any order.

A reader refuses text that is not an image of P1 before it matches anything, and refuses it as not
an image rather than failing in some other way. So a machine that was read answers every text it is
asked about.

## What an image accepts

An image accepts a text, a sequence of scalar values, where a walk from state 0 reads the whole of
it and ends at a state that accepts. A walk reads a scalar value by a step over a set that holds it,
to the state the step names, and moves by a free step to the state it names without reading
anything. So an image accepts the empty text where state 0, or a state free steps lead to from it,
accepts.

The kind changes nothing of what an image accepts. It says that the machine is deterministic, which
a reader holds it to, and which a matcher may walk it faster for.

## Readers and writers

An implementation may read P1 without writing it, or write it without reading it, as the README says
of the two entry points.

A writer writes an image of P1 that accepts what the pattern it was written from accepts. Which of
the machines that accept that it writes, how it numbers their sets and states and in which order it
writes their steps, is the writer's. Two writers may write different images of one pattern, and
neither is the right one: images are compared by what they accept, never by their text.

A reader reads every image of P1 no longer than the most characters the README gives a writer, so
it reads whatever a writer of this repository's release writes. It may read longer ones too.

An image is one text. An implementation that has to carry it in pieces, as Java cuts it into strings
of at most 65,535 characters so that each can be a constant of a class file, puts the pieces back
together before it reads; how it cuts them is not part of the format.

## Fixtures

[`p1.txt`](p1.txt) holds images, some of P1 and some not, with what each accepts. Every
implementation that reads P1 runs it, as every implementation runs `suite/`. The lines are written
by hand from this file, not by a writer, and an image that is not one is there for each rule above.
`p1.txt` says at its top how a line is written, including how it writes a character an image may not
hold, such as a space or a line break before or after one.
